# 設計案：通知（Web Push）（2026-11-24、まだ作っていません）

## 条件（開発者）

- サーバーが持つのは、通知の宛先とバスの番号だけ。行き先や時刻は送らない。
- 見る仕組みが改正を見つけたら、そのバスを登録した人に送る。

## 考え方：サーバーは「どのバスか」しか知らない。「あなたの移動にどう関係するか」は端末が決める

```
[見る仕組み（GitHub Actions）]                [通知のサーバー（Cloudflare Workers）]          [端末]
 改正を見つけて公開した                           宛先とバスの番号だけを持つ
   │ POST /notify {feed: "yonezawacity/Yonezawa"}    │
   │ （合言葉つき）                                  │ そのバスを登録した宛先へ送る
   └───────────────────────────────────────────────▶ │ 中身：{feed, change_date}（暗号化）
                                                      └──▶ Apple / Google / Mozilla の配達サービス ──▶ service worker
                                                                                                    │ 端末に保存した登録で判定
                                                                                                    │ （住民の画面と同じ部品）
                                                                                                    ▼
                                                                    「12月1日から『火曜の病院（行き）』が変わります」
```

- **送る中身は、バスの番号と変わる日だけ**です。行き先・停留所・時刻・移動の名前は、サーバーにも配達サービスにも渡りません。
- 中身は、Web Push の決まり（RFC 8291）で暗号化されます。配達サービスからは、送り手（VAPID で名乗る）は分かりますが、中身は読めません。
- 端末の service worker が、通知を受けたときに `catalog.json` と改正のデータを取り、端末に保存した登録で判定します。そのうえで、知らせの文を作ります。
  - 自分の移動が変わるとき：「12月1日（火）から、『火曜の病院（行き）』が変わります」
  - 登録したバスは変わるが、自分の移動は変わらないとき：「米沢市営バスの時刻表が12月1日から変わります。登録した移動は変わりません」
  - iPhone では、受けた通知は必ず表示しなければならず、表示しない通知は送れません。そのため、変わらない場合も短く知らせます。
- 登録は、いまは localStorage にあり、service worker からは読めません。そこで、IndexedDB にも同じ内容を置きます（端末の中だけ）。

## サーバーに置くもの（これだけ）

| 項目 | 中身 | なぜ要るか |
|---|---|---|
| 宛先 | ブラウザが発行する宛先 URL（Apple / Google / Mozilla の配達サービスの URL）と、暗号の鍵（p256dh・auth） | 通知を送るため |
| バスの番号 | `yonezawacity/Yonezawa` のようなフィードの番号の一覧 | どの改正のときに送るかを決めるため |
| 日時 | 登録した日時・最後に更新した日時 | 長く使われない宛先を消すため |

名前・メールアドレス・停留所・時刻・位置・端末の情報は置きません。アカウントも作りません。

## 使うサービスの候補と費用

| 候補 | 費用 | よい点 | 気になる点 |
|---|---|---|---|
| **Cloudflare Workers ＋ Workers KV（おすすめ）** | 無料の範囲：リクエスト 10万回／日、KV の読み 10万回／日・書き 1,000回／日 | 自分で持つので、宛先が第三者の分析に使われない。GitHub Actions から呼びやすい | 無料プランは、1回の呼び出しで外へ出せるリクエストが50まで。通知を送る相手が50を超えるときは、Actions から何回かに分けて呼ぶ（または有料プラン 月5ドル） |
| Firebase Cloud Messaging | 無料 | 送る仕組みが用意されている | Google の部品を端末に入れる。宛先が Google のサービスに置かれる |
| OneSignal など通知の専門サービス | 無料のプランあり | 管理の画面がある | 宛先と使い方の記録が第三者に置かれ、分析にも使われうる。条件「サーバーが持つのは宛先とバスの番号だけ」を守りにくい |
| 小さなサーバー（VPS）を借りる | 月500〜1,000円ほど | 自由に作れる | 保守（更新・障害対応）の手間 |

**見込み**：登録した人が1,000人、1つのバスの改正で100人に送るとすると、送るたびのリクエストは100回ほどで、1日の上限（10万回）に十分収まります。KV の書き込みは、登録と更新のときだけです。

- Workers の上限（1日10万リクエスト、1回の呼び出しで外へのリクエスト50）は、Cloudflare の公式の説明で確かめました。
- D1（データベース）の無料の範囲は、確かめられませんでした。そのため、宛先の置き場所は KV にする案です。

## 開発者に用意していただくもの

1. **Cloudflare のアカウント**（無料）。Workers のサブドメイン（`○○.workers.dev`）で動かせるので、自分のドメインは要りません。
2. **VAPID の鍵の組**：私が作れます。秘密の鍵は Workers の Secrets に入れていただき、ファイルにもリポジトリにも置きません。公開の鍵はアプリに入れます。
3. **合言葉（NOTIFY_TOKEN）**：GitHub Actions が通知のサーバーを呼ぶときに使います。GitHub の Secrets と Workers の Secrets の両方に、同じ値を入れていただきます。
4. VAPID の連絡先（`mailto:` か URL）：配達サービスが、送り手に連絡するときに使います。`GTFS_CONTACT` と同じアドレスでよければ、それを使います。

## アプリの側で足すもの

- `manifest.webmanifest`（名前・アイコン・`display: standalone`・`id`）と、アイコンの画像
- service worker（`sw.js`）：通知を受けて判定し、表示する。押されたらその移動の画面を開く
- 設定の画面：「知らせを受け取る」「知らせを止める」のボタン。登録した移動が変わったら、サーバーのバスの番号の一覧も直す

## iPhone で必要な手順（使う人）

1. iOS／iPadOS 16.4 以降にする。
2. Safari でアプリを開き、共有ボタン →「ホーム画面に追加」を押す。
3. ホーム画面のアイコンから開く（Safari のままでは通知を受けられません）。
4. アプリの「知らせを受け取る」を押し、出てきた確認で「許可」を押す。
   - 確認は、ボタンを押したときにしか出せない決まりです。
   - 一度「許可しない」を押すと、確認は二度と出ません。iPhone の「設定 → 通知 → まちの足カルテ」から許可していただく必要があります。

この手順を、画面と紙の両方で案内します。高齢の方には、家族や窓口の人が設定を手伝う前提の案内にするのがよいと考えます。

## 通知を止める方法

- アプリの「知らせを止める」：端末の受け取りをやめ、サーバーから宛先を消します。
- iPhone の「設定 → 通知 → まちの足カルテ」でオフにする（サーバーの宛先は残りますが、届いても表示されません）。
- ホーム画面からアイコンを消す。
- サーバーは、配達サービスから「この宛先はもう無い」（404／410）と返ってきた宛先を消します。1年間更新の無い宛先も消します。

## 利用規約・プライバシーの説明に書くべきこと

**プライバシーの説明**
- 集めるもの：通知の宛先（配達サービスが発行する URL と暗号の鍵）、登録したバスの番号、登録と更新の日時
- 集めないもの：名前、メールアドレス、停留所、時刻、移動の名前、位置。これらは端末の中だけにあり、外へ送りません。
- 使う目的：登録したバスの時刻表が変わることを知らせるためだけ
- 預ける先：Cloudflare（通知のサーバー）、Apple・Google・Mozilla（配達サービス。中身は暗号化されて読めません）、GitHub（アプリと時刻表のデータの配信。アクセスの記録は GitHub の方針による）
- 残す期間と消し方：「知らせを止める」で消える。届かなくなった宛先と、1年間更新の無い宛先は自動で消す
- 分析・広告：しない。Cookie も使わない
- 問い合わせの先

**利用規約**
- 時刻表のデータは、GTFSデータリポジトリで公開されているデータを加工したもので、正しさは保証しません。乗る前に、事業者の時刻表で確かめてください。
- 通知は、届かない・遅れることがあります（定時の実行が遅れる、配達サービスの都合など）。
- 予告なく止めたり、変えたりすることがあります。
- 出典とライセンス（フィードごとのライセンス、付帯データの CC BY 4.0）
