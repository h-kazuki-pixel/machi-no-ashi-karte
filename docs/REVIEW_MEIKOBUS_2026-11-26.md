## 「くらべられない」が38%になった理由

- 置き換わったときの改正は、「前の中身」と「後の中身」の2つだけで作る。
- 前の中身は 12/1 からしか有効でない。そのため、変わる日 12/4 より前で比べられる日は、12/1（火）〜12/3（木）の3日だけだった。
- それより前の日は「この日に有効な時刻表のデータが無い」になり、実際に動いている版（4622628b）につながなかった。
- そのため、月・金・土・日の移動は、「前」が0日で「くらべられない」になった。火〜木の移動も、比べた日が1日で「比べた日が少ない」が付いた。

**こちらの比べ方の問題で、明光バスのデータの問題ではない。**

| 乗る → 降りる | 日 | 前 | 後 |
|---|---|---|---|
| 庄川口 → 南紀の台下（11:59までに着く） | 12/14（月） | なし（比べる日が無い） | 11:36発 → 11:51着 |
| 滝内 → 鶴ヶ丘（13:46までに着く） | 12/4（金） | なし（比べる日が無い） | 13:30発 → 13:46着 |
| 白浜駅 → アドベンチャーワールド（15:28よりあとに乗る） | 12/12（土） | なし（比べる日が無い） | 15:37発 → 15:45着 |

- ほかの段階は「変わらない」（62.5%）だけ。例：
  - 戸土 → 北郡：12/3（木）、18:36発 → 18:41着で同じ
  - 寒サ浦 → 走り湯：12/2（水）、13:07発 → 13:16着で同じ
  - 千畳口 → 三段壁：12/9（水）、8:19発 → 8:20着で同じ

## C と「のりばの場所が動いています」の決まりはぶつかるか

いまの決まりは、**同じ停留所 ID のまま、場所が50m以上動いたとき**に「◯◯ののりばの場所が、データの上で約◯m 動いています。現地の案内を確かめてください。」と出す（改正の停留所の報告の moved_m）。

- 今回は、ID が `11_03` から `11_01` に変わった（両方とも前からある別ののりば）。距離は約22m。
  - この決まりの対象ではなく、C を入れても入れなくても、この注意は出ない。
  - 今回については、ぶつからない。
- ただし、すき間がある。
  - 同じ名前の **別の ID ののりばに移り、そこが50m以上離れている**場合も、いまの決まりでは注意が出ない。
  - C をそのまま入れると、そういう変更も「のりばだけの変更」として黙って通ってしまう。
- そこで C は、次の形にするのがよい（**C′**）。
  - のりばの番号だけが変わり、移った先が前ののりばから **50m 未満**のとき：改正にしない。
  - **50m 以上**離れたのりばに移る便があるとき：改正として扱う。移動の画面に「◯◯ののりばが、約◯m 離れた所に変わります。現地の案内を確かめてください。」と出す。これは新しい表示なので、文面を見ていただいてから作る。

**のりばが変わる停留所（紀伊田辺駅）を登録している人に、何がどう見えるか**
- アプリは、停留所を名前でまとめて扱う。のりばの番号は、どの画面にも出していない。
- いま（承認していない状態）：紀伊田辺駅と長野線の停留所の移動は、時刻は前と同じに出る。のりばが変わったことは、どこにも出ない。12/5 の改正の結果も、時刻が同じなので変わらない。
- 承認した場合：
  - 12/4 の改正が別にでき、月・金の移動は「くらべられません」になる。
  - 知らせを受け取る設定なら、12/4 の知らせが届く。
  - のりばが変わったことは、やはり出ない。
- C（C′）を入れた場合：いまと同じ。今回は22mなので、のりばの注意も出ない。

## 決まったこと（2026-11-26、開発者）

- 明光バス（8af5b399）は承認しない。A・B・C′・D をすべて入れる。
- A に足す：公開中の改正を新しい中身で上書きするとき、便や時刻が前の中身と違い、その改正の知らせをもう送っていた場合は、
  もう一度だけ知らせる。文は「◯◯バスの、◯月◯日からの時刻表が、もう一度変わりました。」。
  のりばだけの違いのときと、まだ知らせを送っていないときは送らない。
